## O QUE E O CRONUS

Uma **linguagem de programacao declarativa** compilada em Rust. Um arquivo `.cronus` vira um app web completo: servidor HTTP, banco SQLite, API REST, GraphQL, UI renderizada, auth JWT, docs automaticos -- tudo num binario de **6.5MB**.

```cronus
app "Meu App" {
  stack fullstack
  port 3000
  database sqlite "./data.db"
}

entity Task {
  title string required
  status enum ["todo", "doing", "done"] required

  transition status {
    todo -> doing -> done
  }

  on create {
    log "Task created"
  }
}

page "/" type:custom {
  section table style:dark {
    columns "Title, Status"
    bind Task { query all }
  }
}
```

Isso gera: servidor na porta 3000, tabela Task no SQLite, CRUD API em /api/tasks, state machine validada, effect hooks, pagina com tabela de dados ao vivo, auth, docs em /docs.

## O QUE FOI FEITO (COMPLETO)

### 1. Major Refactor -- Modularizacao

O codebase foi reestruturado de arquivos monoliticos para modulos:

- **main.rs**: De ~9,500 para 3,782 linhas (-60%)
- **parser.rs**: Dividido em `parser/mod.rs` + `ast.rs` + `tokenizer.rs`
- **ui.rs**: De ~12,500 para `ui/` com 13 arquivos (mod.rs = 907 linhas, -88%)
- **CLI**: 30 comandos extraidos para `src/cli/`
- **Server**: 6 arquivos em `src/server/` (api, docs, auth_pages, response, state)

### 2. Linguagem -- Features Completas

- **Doc-comments `///`** -- parsed no AST com `@tags` estruturados
- **Constitution block** -- `constitution { must "..." never "..." }` validado contra AST
- **`shared` keyword** -- `entity X shared {}` pula filtro _owner_id
- **Webhooks** -- `webhook /entity { on create -> POST "url" }`
- **SQL validation** -- P040/P041 rejeitam identificadores invalidos e reserved words
- **Transitions** -- `transition status { draft -> review -> published }` state machines
- **Inline constraints** -- `price integer required!` com `!` syntax
- **Default values** -- `status enum [...] default:"draft"`
- **Effects** -- `on create/update/delete { ... }` blocks em entities
- **Resolve pass** -- Symbol table, dead reference detection, type checks (924 lines)
- **AI-Error Protocol** -- `--strict-ai` gera JSON machine-readable para AI consumption

### 3. Enforcement -- 13 Regras Inquebraveis

```
C001  no-dead-text         Metricas hardcoded em templates         ERROR
C002  no-sensitive-render  Campos sensitive no HTML/API            ERROR
C003  bind-or-empty        Secoes de dados sem bind/items          ERROR
C010  no-dead-links        Links internos pra rotas inexistentes   ERROR
C011  no-dead-ui           Botoes sem action handler               WARNING
C012  form-submit-handler  Forms sem submit                        WARNING
C020  no-orphan-reload     location.reload() no codigo             ERROR
C030  shared-entity-auth   Mutacao publica em entity shared        ERROR
C031  no-sensitive-select  Campo sensitive em columns/bind         ERROR
P040  identifier-valid     Identificador SQL invalido              FATAL
P041  sql-reserved         Palavra reservada SQL como nome         FATAL
      no-fake-state        "Loading" em HTML estatico              WARNING
      no-hardcode-user     "System Admin" em HTML                  WARNING
```

### 4. Security Hardening

- **Argon2id** para passwords (fallback SHA-256 para migracao)
- **Rate limiting**: 10/60s auth, 100/60s API
- **CSP nonces** per-request em todo `<script>`
- **XSS safe by design**: `{{}}` escapes automaticamente, html_escape() everywhere
- **Immutable audit trail**: SHA-256 hash chain + diff tracking (before/after)
- **Data isolation**: _owner_id + `shared` keyword
- **Secure cookies**: HttpOnly, Secure, SameSite=Strict
- **SQL injection**: Parser P040/P041 bloqueia no parse time
- **Atomic transactions**: DB mutations em transacoes

## REGRAS INVIOLAVEIS

1. **ZERO hardcode** -- tudo vem do DB ou API. Lint C001 bloqueia build.
2. **ZERO dados fake** -- DB comeca vazio. Empty states obrigatorios.
3. **ZERO location.reload()** -- CRONUS.reload() para soft refresh. Lint C020 bloqueia.
4. **Sensitive nunca no output** -- password nunca aparece em HTML/API. Lint C002/C031.
5. **Tudo em tempo real** -- mutations disparam SSE + auto-reload. SPA navigation obrigatoria.
6. **Codigo se documenta** -- `///` doc-comments entram no AST e geram /docs.
7. **Constitution inline** -- regras de negocio no codigo, validadas automaticamente.
8. **XSS safe by design** -- `{{}}` auto-escapes, nunca raw HTML de user input.
9. **Immutable audit** -- audit trail e append-only com hash chain. Nunca deletar.
10. **Atomic transactions** -- DB mutations em transacoes, nunca operacoes parciais.
