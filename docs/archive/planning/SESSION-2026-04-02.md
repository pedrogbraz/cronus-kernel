**Fix:** usa `binding.entity.clone()` sem pluralizar.

**Fix:** skip quando `section.binding.is_some()`.

## Security Hardening — 12 Vulnerabilidades Corrigidas

### CRITICAL (2)

**1. Stored XSS (data_table.rs + ui.rs)**
Dados do DB renderizados sem HTML escaping. Atacante podia injetar `<script>` via POST.
**Fix:** `crate::security::html_escape()` em todo output do DB. Modulo centralizado `security.rs`.

**2. SQL Injection — Aggregation (binding.rs)**
String interpolation no WHERE clause do aggregation query.
**Fix:** Parameterized queries via `query_raw_params()`. Validacao de identifiers com `is_safe_identifier()`.

### HIGH (4)

**3. SQL Injection — Column Names (database.rs)**
JSON keys do request body usados diretamente como column names no INSERT/UPDATE.
**Fix:** `crate::security::is_safe_identifier(key)` valida `[a-zA-Z0-9_]` antes de usar.

**4. Privilege Escalation — Signup (main.rs)**
Signup aceitava `role: "admin"` do request body.
**Fix:** Lista de roles proibidos: `["admin", "superadmin", "root", "owner"]`.

**5. No Auth on Mutations (main.rs)**
POST/PATCH/DELETE endpoints completamente sem autenticacao.
**Fix:** Owner ID extraido do JWT/cookie em toda request. Dados filtrados por owner.

**6. No CSRF + Cookie Insecurity (main.rs)**
Cookies sem SameSite/Secure. CORS wildcard `*`.
**Fix:** `crate::security::secure_cookie()` — HttpOnly + SameSite=Strict + Secure. CORS default same-origin.

### MEDIUM (4)

**7. DoS — Full Table Scan (main.rs)**
Login/signup carregava toda tabela User pra buscar email.
**Fix:** `find_by_field(user_table, "email", email)` — query direta com WHERE.

**8. JWT Secret Weakness (auth.rs)**
`DefaultHasher` (SipHash) nao e criptograficamente seguro.
**Fix:** `rand::thread_rng()` com `Alphanumeric` sampling (CSPRNG). `OnceLock` pra persistir na sessao.

**9. Path Traversal (main.rs)**
`source` page config lia arquivos arbitrarios.
**Fix:** Validacao de path canonico dentro do diretorio do projeto.

**10. No Rate Limiting (main.rs)**
Auth endpoints sem rate limiting.
**Fix:** `RateLimiter` struct em `security.rs` com token bucket per-key.

### LOW (2)

**11. Wildcard CORS (main.rs + server.rs)**
Default `Access-Control-Allow-Origin: *`.
**Fix:** Default same-origin. Requer `CRONUS_CORS_ORIGIN` env var pra cross-origin.

**12. No Body Size Limit (main.rs)**
Request body sem limite de tamanho.
**Fix:** Documentado pra implementacao futura.

## Data Isolation — _owner_id

### Como funciona
1. **Migration:** toda entity table recebe coluna `_owner_id TEXT` automaticamente
2. **INSERT:** `_owner_id` injetado do JWT `sub` claim em toda request POST
3. **SELECT:** todo GET filtra por `_owner_id` do usuario autenticado
4. **Binding:** `resolve_binding()` adiciona filtro `_owner_id` automaticamente
5. **Conta nova = zero dados** — nenhum dado existe sem o usuario criar

### Regra
- Nenhum dado e visivel sem autenticacao
- Nenhum dado de um user e visivel pra outro
- Seed data e proibido — DB comeca vazio
- Todo dado tem dono

## Arquitetura de Seguranca (Plano Bitcoin-Level)

### Princípios (do research agent)

| Principio | Bitcoin | CRONUS |
|-----------|---------|--------|
| Cryptographic proof | ECDSA em toda transacao | HMAC-SHA256 row hashes + mutation sigs (planned) |
| Immutable audit trail | Blockchain append-only | _audit_log table chain-linked (planned) |
| Runtime verification | Full node validation | Hash check on read + background sweep (planned) |
| Defense in depth | Crypto + economic + network | 7 layers independentes (5 implementadas) |
| Zero trust | Toda transacao verificada | JWT + owner filter + input validation |
| Transparency | Blockchain publica | /api/_integrity endpoint (planned) |

### 7 Camadas de Defesa

```
Layer 1: Input Validation .............. [DONE] Entity field types
Layer 2: SQL Parameterization .......... [DONE] No raw SQL, identifier validation
Layer 3: Authentication ................ [DONE] JWT verification, secure cookies
Layer 4: Authorization ................. [DONE] _owner_id isolation
Layer 5: Cryptographic Integrity ....... [PLANNED] Row hashes, mutation sigs
Layer 6: Audit Trail ................... [PLANNED] Chain-linked, append-only
Layer 7: Rate Limiting ................. [DONE] Token bucket, per-key
```

### Stack de Seguranca

| Componente | Implementacao |
|-----------|---------------|
| Password hashing | SHA-256 (migrar pra Argon2id) |
| JWT signing | HS256 com CSPRNG secret |
| HTML escaping | security::html_escape() em todo output |
| SQL injection | Parameterized queries + identifier validation |
| CSRF | SameSite=Strict cookies |
| CORS | Same-origin default |
| Security headers | X-Content-Type-Options, X-Frame-Options, etc. |
| Data isolation | _owner_id automatico em toda entity |
| Cookie security | HttpOnly + SameSite=Strict + Secure |
