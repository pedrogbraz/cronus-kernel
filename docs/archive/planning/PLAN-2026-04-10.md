### 2.4 Bug confirmado: dumper emite HEAD/OPTIONS e gera `.cronus` unparseable

**Status**: ✓ **CORRIGIDO** em 2026-04-10.

**A hipótese inicial estava errada.** Eu suspeitei de "silent coerce" no parser porque vi `unwrap_or(HttpMethod::GET)` em `src/parser/mod.rs:701`. Verificação empírica derrubou a hipótese.

**Verificação empírica (`cronus parse /tmp/test-head.cronus`)**:
```
Parse error: Linha 4: esperava Method, encontrou 'HEAD' (Identifier)
```

**Por quê**: `src/parser/tokenizer.rs:45` declara `METHODS = &["GET", "POST", "PATCH", "PUT", "DELETE"]`. Palavras fora dessa lista são tokenizadas como `Identifier`, não `Method`. O `expect(TokenKind::Method)` em `src/parser/mod.rs:700` então falha com erro claro. O `.unwrap_or(HttpMethod::GET)` da linha 701 é **código defensivo morto** — nunca roda porque o tokenizer filtra antes.

**Bug real** (agora corrigido): `src/dump/nextjs.rs` tinha duas partes defeituosas:
- Linha 598-610: `detect_exported_methods` escaneava por `HEAD`/`OPTIONS` em arquivos Next.js
- Linha 1281-1293: loop emite **cada método como texto** no `.cronus` (`handle HEAD /foo auth:jwt`)

Resultado: dumps de projetos Next.js com rotas HEAD/OPTIONS geravam `.cronus` que falhava no parse com o erro genérico acima.

**Fix aplicado** (`src/dump/nextjs.rs` `detect_exported_methods`):
```rust
for method in &["GET", "POST", "PUT", "PATCH", "DELETE"] {  // HEAD/OPTIONS removidos
    …
}
```

Comentário explicativo adicionado no código. Dois testes inline adicionados em `src/dump/nextjs.rs`:
- `detect_exported_methods_skips_head_and_options`
- `detect_exported_methods_returns_empty_for_non_route`

**`cargo test`**: 203 → 205 passing.

**O que NÃO foi feito** (decisão intencional):
- Não toquei no `.unwrap_or(HttpMethod::GET)` de `parser/mod.rs:701`. É código defensivo morto mas não é bug — apenas reflete intenção mal alinhada com a realidade do tokenizer. Deixa pra próxima limpeza.
- Não melhorei a mensagem de erro do parser. O atual (`esperava Method, encontrou 'HEAD' (Identifier)`) é adequado. UX polish fica pra outra rodada.
- Não adicionei HEAD/OPTIONS à linguagem. É feature, não fix. Design decision pro dono.
